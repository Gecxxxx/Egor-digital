## Запуск и проверка

1. Выбрать площадку и её формат. Проверить лимиты текста и требования к изображениям; универсальные макеты могут потребовать адаптации.
2. Использовать preview-домен с настроенным /api/brief. Ссылки в материалах используют будущий production URL: заменить origin на подтверждённый preview либо дождаться отдельного разрешённого выпуска.
3. Для стейджинга не копировать production-секреты во фронтенд. Маршруты формы используют относительный /api/brief; статический preview без backend не отправляет обращения, а показывает ошибку. Telegram остаётся прямым запасным контактом.
4. Перед рекламой проверить на целевом хостинге отправку с согласия пользователя и ответ { ok: true }. Локальные QA используют заглушку API, реальные обращения не создаются.
5. В Метрике 111655243 проверить существующие цели lead_form_start, lead_form_success, telegram_click, whatsapp_click, form_error. Дополнительные события campaign_view и campaign_cta_click передают только offer и расположение действия.
6. utm_source — реальный источник, utm_medium — тип размещения, utm_campaign — site-fix / landing-page / lead-system, utm_content — ad-1 / ad-2 / ad-3. First-touch сохраняется в sessionStorage.

## Учёт результата

Дата, источник, offer, utm_content, расход, переходы, подтверждённые формы, диалоги в мессенджере, подходящие задачи, предложения, предоплаты.

Цена обращения = расход / подтверждённые обращения, если обращений больше нуля. Мессенджерный клик не означает обращение. При малом числе наблюдений не объявлять вариант победителем. Оценивать также соответствие задач объёму предложения и время выполнения.
